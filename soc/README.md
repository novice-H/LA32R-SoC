# SoC 硬件资源与当前状态

核对日期：2026-11-14；最新硬件提交：`8ec0463`，已通过合并提交 `eae1d4c` 纳入 `game2048`（保留软件提交 `5d8459b`）。本页描述当前 RTL、构建脚本和实际检查结果；`docs/design.md` 保留设计背景，实施状态和当前映射以本页及源码为准。

## 1. 已接通的系统

```text
thinpad_top（板级引脚，50 MHz）
  └─ soc_top
      ├─ core_top（openLA500，AXI3 主口）
      │    └─ axi_slave_wrap（bus/axi_slave_ref.v，AXI 从口 → 简单总线）
      │         └─ soc_bus（译码、请求握手、统一响应）
      │             ├─ base_ram_ctrl → BaseRAM
      │             ├─ ext_ram_arbiter → ext_ram_ctrl → ExtRAM
      │             └─ confreg → 按键/拨码/LED/数码管
      └─ vga_fb → ext_ram_arbiter → ExtRAM
          ↔ confreg 的 fb_sel / vsync_start 翻页握手
```

实际入口为 `thinpad_top.v`，已完成板级封装。CPU 和扫描器共用 50 MHz，视频时钟直接转发该时钟。`reset_btn` 经两级采样产生系统复位；测试台显式保持复位 20 拍后释放。备用时钟 `clk_11M0592` 与 `clock_btn` 保留引脚，当前功能使用主时钟和复位按钮。

CPU 源码包含整数乘除、指令/数据 cache、CSR、TLB 与 AXI 主接口。`soc_top` 将外部中断输入固定为 0，只保留写回 PC 供仿真观察；正式 FPGA 构建加载 cache 的 `.xcix` IP，仿真定义 `SIMU` 使用行为存储模型。CPU 各功能的覆盖程度需按测试逐项确认。

`sram_axi_bridge.v` 是另一独立的“类 SRAM 请求 → AXI 主口”模块，当前 `soc_top` 使用 CPU 自带 AXI 主口和 `axi_slave_wrap`。两种桥分别位于协议链的不同位置；独立桥的测试结果单独记录。

## 2. 存储和地址映射

以下范围是 `bus/soc_bus.v` 接收的总线地址；CPU 复位时 `DA=1, PG=0`，按直接地址模式取指。

| 资源 | 主地址范围 | 兼容别名 | 地址窗口 |
| --- | --- | --- | --- |
| BaseRAM | `0x1C000000`～`0x1C3FFFFF` | `0x80000000`～`0x803FFFFF` | 4 MiB，程序/数据/栈规划区 |
| ExtRAM | `0x1C400000`～`0x1C7FFFFF` | `0xA0000000`～`0xA03FFFFF` | 4 MiB，帧缓冲和其他数据规划区 |
| confreg | `0xBFD00000`～`0xBFD000FF` | — | 256 B 译码窗口 |

RAM 引脚为 20 位字地址、32 位数据，控制器接收 `byte_addr[21:2]`，带 4 位低有效字节使能。主地址与兼容别名命中同一物理存储；管理内存时只计算一份容量。板卡实际 SRAM 型号与可用容量仍需结合板卡资料/实测核对。

**启动入口采用 `0x1C000000`**：CPU `if_stage.v` 复位逻辑给出该首条取指地址，汇编与 `sw/boot/link.ld` 的 C++ 自检均在此链接。C++ 启动层设置栈顶 `0x1C400000`，链接脚本预留 16 KiB 栈，并检查其与数据区的间隔。

CPU 复位时 `DATF=DATM=0`。后续开启 cache/分页时，帧缓冲和 MMIO 的存储属性应由 CSR/DMW/TLB 配置及一致性方案明确规定；总线地址别名本身只决定存储译码。建议初期沿用直接地址路径。

当前总线将请求接收后的响应统一到第 2 拍；ExtRAM 请求还需等待仲裁授权。当前参考 AXI 从桥面向 32 位字访问、至多 4 拍的突发与写字节掩码；窄访问、响应背压及不同桥实现需单独验证。板级 MMIO 和首版显存绘制优先使用 4 字节对齐的 `uint32_t` 访问。

## 3. 板载资源与寄存器

所有寄存器相对 `0xBFD00000`，访问优先使用 32 位读写：

| 偏移 | 寄存器 | 当前 RTL 行为 |
| --- | --- | --- |
| `0x00` | STEP | 可读写低 12 位；输出显示饱和到 3199，LED[4:0] 为百位以上，双数码管显示末两位 |
| `0x04` | STATUS | 可读写位[15:5]，映射 LED[15:5]；约定 bit15=AI、14=LOSE、13=WIN、12:5=调试 |
| `0x08` | BTN | bit0=上、1=左、2=下、3=右；两级同步后上升沿累积，读取后清零 |
| `0x0C` | KEY | 返回 `dip_sw[1:0]`；约定 bit0=游戏开关、bit1=AI，手动版按游戏需求处理 |
| `0x10` | TIME | 50 MHz 下每 50000 拍增加 1，即毫秒计数 |
| `0x14` | RAND | 每拍递增的 32 位自由计数，可作为软件伪随机发生器的种子 |
| `0x18` | FB_CTRL | bit0 写1请求翻页，垂直消隐起点翻转并清请求；bit16读当前显示缓冲号 |

BTN 使用事件位累积，同一方向的多次按压在读取前合并为一个置位位；多方向同时置位时由软件确定处理顺序。按键读清与新边沿同拍时，当前赋值顺序以读清为准；RTL 依赖板级消抖，机械按键实际表现需上板确认。KEY 直接反映拨码低两位，硬件引出的其余拨码位当前未接入软件寄存器。

RAND 是计数器，软件应初始化伪随机状态后生成方块，测试时保留固定种子路径。手动版将 AI 状态位保持 0 即可，AI 为选做。

UART：TX 固定空闲高电平、RX 未用于 SoC 功能。Flash：片选及读写关闭、数据高阻。固件当前由仿真 RAM 预装加载；板上程序加载/复位顺序仍待实现和验证。

## 4. 视频与双帧缓冲

| 项目 | 当前参数 |
| --- | --- |
| 有效区 | 800×600 |
| 行总长 / 同步起止 | 1040 / 856～976（末端不含） |
| 场总长 / 同步起止 | 666 / 637～643（末端不含） |
| 像素钟 / 刷新率 | 50 MHz / 约 72.19 Hz（按参数计算） |
| 像素格式 | RGB332：R[7:5]、G[4:2]、B[1:0] |
| 帧大小 / 行跨度 | 480000 B / 800 B |
| FB0 | `0x1C400000`，兼容别名 `0xA0000000` |
| FB1 | `0x1C480000`，兼容别名 `0xA0080000` |

两缓冲基址相差 `0x80000`；每帧有效区域为 480000 B。四个像素按小端顺序打包为一个 32 位字，像素字节偏移为 `y*800+x`。显示扫描通过仲裁器优先访问 ExtRAM；`dvi_next` 提前预警，CPU 在显示取数间隙获得访问机会。

软件读 FB_CTRL bit16 识别前台，在另一缓冲画完后写 bit0=1，再等待硬件翻转并确认请求清除。该连线已在 `soc_top` 中接入，现有 `sw/drv/framebuffer.cpp` 通过 `begin/present` 实现该协议，在提交前执行 DBAR 0。CPU 整机已验证正常翻页、零等待期限超时及后续恢复；完整手动游戏连续显示仍待平台后端接入。

参考提交 `210313455329849aa7fc2d73eb6550c1abfb21d5` 的 `soc/` 与当前 HEAD 一致。参考 `start_v2.S` 以 120000 次整字写填充 FB0，并用首尾行/四像素边框检验显示；用户报告该版本已实板验证。本次新增 C++ 绘图/翻页驱动沿用同一地址及格式，本轮保持 RTL 和已交付 bit。
